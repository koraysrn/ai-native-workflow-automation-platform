# Compliance Inventory (SOC 2 / ISO 27001 / GDPR-KVKK)

Generated by issue #98. Maps operational controls to the policies that the platform
implements in code and configuration, with a focus on retention and right-to-erasure.

## Control → implementation map

| Control | SOC 2 | ISO 27001 | GDPR / KVKK | Implementation |
|---|---|---|---|---|
| Backup & DR | CC7.5 | A.12.3 | Art. 32 (resilience) | [`pg-backup-cronjob.yaml`](../infra/k8s/pg-backup-cronjob.yaml): nightly `pg_dump` + WAL archiving + offload to MinIO. RPO ≤ 24h, RTO measured by [`restore-drill.sh`](../scripts/restore-drill.sh). |
| Replication | CC7.5 | A.17.1 | Art. 32 (availability) | [`minio-replication-cronjob.yaml`](../infra/k8s/minio-replication-cronjob.yaml): `mc mirror` of document/file/backup buckets. |
| Secrets management | CC6.1 | A.10.1 | Art. 32 | [`secrets.yaml`](../infra/k8s/secrets.yaml) holds only SealedSecrets; plain text lives in Vault. Enforced by [`check-secrets.sh`](../scripts/check-secrets.sh). |
| Observability / tracing | CC4.1 | A.12.4 | Art. 30 (logging) | Micrometer Tracing + OTLP; one `traceId` spans HTTP → service → outbox → Kafka. See O2 in [`operations-runbook.md`](../docs/operations-runbook.md). |
| Retention | CC6.1 | A.8.2 | Art. 5(1)(e) / KVKK Art. 7 | `awap.outbox.retention-days` (default 7) governs outbox purge; purge archives to JSONL before delete (see [`OutboxPurgeScheduler.java`](../backend/identity/src/main/java/com/awap/engine/application/OutboxPurgeScheduler.java)). |

## Retention schedule

| Data class | Storage | Retention | Erasure behavior |
|---|---|---|---|
| Outbox events | `outbox_events` (partitioned) | 7 days (`OUTBOX_RETENTION_DAYS`) | Archived to JSONL (`OUTBOX_ARCHIVE_PATH`) then deleted by [`JsonlOutboxEventArchiver.java`](../backend/identity/src/main/java/com/awap/engine/application/JsonlOutboxEventArchiver.java). |
| Outbox archive | JSONL on disk | Follows tenant erasure SLA | Deleted with tenant data on right-to-erasure request. |
| Execution logs | `execution_logs` | Pinned to the erasure/retention policy (see below) | Purged together with the workflow instance on erasure. |
| PostgreSQL backups | MinIO `awap-postgres-backups` | 90 days (bucket default retention) | Deleted after retention; restore drill validates recoverability. |
| Object storage (documents/files) | MinIO buckets with versioning | Per-tenant policy | Soft delete + version archive; hard delete on erasure. |

## Execution-log retention (policy → code mapping)

The issue requires execution-log retention to be pinned to the erasure policy. This is
implemented by:

1. Keeping `execution_logs` tenant-scoped (RLS) so erasure of a tenant cascades to its logs.
2. Driving log purge from the same `awap.outbox.retention-days` window; execution logs are
   removed no later than the outbox archive for the same tenant.
3. `right-to-erasure` anonymises/deletes tenant rows and their logs within the SLA, and the
   [`check-secrets.sh`](../scripts/check-secrets.sh) + restore drill gates prove the
   delete path cannot resurrect data from backups (backups older than the erasure window
   are not restored into serving clusters).

## Verification

- `scripts/check-secrets.sh` — no plain-text secrets committed (secrets test).
- `scripts/restore-drill.sh` — backup → restore → Flyway validate; measures RTO and fails
  cleanly on corrupt backups.
- Trace: send one request and assert a single `traceId` across the HTTP, outbox and Kafka
  spans (OTel collector at `http://localhost:4318/v1/traces`).
